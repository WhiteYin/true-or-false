# 真的假的.com：首页设计与实施要求

## 一、本轮目标

制作可点击的响应式首页，同时适配 PC 与移动端。先完成视觉和前端交互，真实新闻检索、模型判断、数据库与后台任务留待后续接入。

当前项目路径：`E:\codex\真的假的`。

本轮尚未创建页面代码。实施前检查目录现状，保留已有文件。

## 二、已确认的需求

| 项目 | 要求 |
|---|---|
| 视觉风格 | 鲜明品牌式，大字标题、强对比配色 |
| 主标题 | **真的假的.com** |
| 主按钮 | **辨真假** |
| 输入方式 | 多行文字输入，支持直接粘贴新闻链接 |
| 图片 | 提供图片选择入口、预览与移除功能 |
| 辅助内容 | 一句简短说明、示例问题、底部核查说明 |
| PC 布局 | 主体居中并限制宽度 |
| 移动端布局 | 单列排列，按钮位于输入框下方 |
| 交付 | 可实际点击操作的响应式首页 |

## 三、视觉建议

建议以**明黄色、墨黑色、白色**构成品牌配色：大字标题形成视觉重点，白色输入区保证阅读和编辑体验。

该配色是建议默认值，用户已确认的是“大字标题与强对比风格”，尚未单独确认具体色值。

- 背景：暖白或浅黄色。
- 标题：墨黑色粗体中文无衬线字体，`.com` 可适当缩小，但保持整体品牌识别。
- 强调色：明黄色，用于品牌装饰或重点区域。
- 输入区：白底、清晰边框、适度圆角。
- 主按钮：黑底浅色字，具有明确的悬停、按下和键盘焦点状态。
- 保持充足留白，避免堆叠新闻配图、仪表盘和装饰卡片。
- 不依赖颜色单独传达状态。

## 四、页面结构与文案

页面从上到下：

1. **主标题：** 真的假的.com
2. **简短说明：** 别急着转发，先看看证据。
3. **多行输入区**
4. **图片选择入口与图片预览**
5. **主按钮：** 辨真假
6. **示例问题**
7. **底部说明**

输入框应有可访问的标签“待核查内容”，占位文案建议：

> 粘贴一条新闻、一段传言或原文链接……  
> 也可以添加截图，补充你想核实的内容。

图片入口文案：**添加截图**。

示例区标题：**没想好查什么？试试这些示例**

示例题目明确属于演示输入，不代表已发生的新闻或已有核查结果：

- 某地从下个月起全面实行四天工作制？
- 网传这项新规今天开始执行，是真的吗？
- 这张新闻截图是最近发布的吗？

底部说明：

> 核查基于可获取的公开资料，结论可能随新证据更新。查不到，不等于假。

原型阶段另显示一条简短提示：

> 首页体验版，核查服务尚未接通。

## 五、PC 与移动端适配

### PC

- 主内容建议最大宽度约 800px，水平居中。
- 主标题突出，字号可在 80～112px 范围内自适应。
- 输入区初始高度约 180～220px。
- 按钮始终位于输入区下方，视觉上作为主要操作。
- 示例问题可横向排列，空间不足时自然换行。
- 不为占满屏幕而增加无关内容。

### 移动端

- 适配至少 320px 宽的屏幕，无横向滚动。
- 页面左右留白约 16～20px。
- 标题根据屏宽缩放，避免品牌名称被挤出屏幕。
- 输入框字号至少 16px，初始高度约 160px。
- 主按钮通栏，点击高度至少 48px。
- 图片预览和示例自然换行或纵向排列。
- 手机键盘弹出后仍可正常滚动、编辑和提交。
- 避免固定高度或固定底栏遮挡内容。

## 六、交互规则

### 文本与链接

- 使用真正的多行文本框。
- Enter 插入换行，不直接提交。
- 文字与链接可以混合输入，无需单独链接字段。
- 初版建议最多 2,000 字，并显示字数。
- 输入框随内容适度增高，到达最大高度后内部滚动。
- 输入错误以邻近文案说明，并保留原内容。

### 图片

- 支持点击选择图片；桌面端可补充拖放。
- 建议支持 JPEG、PNG、WebP，最多 3 张，每张不超过 10MB。
- 显示缩略图及移除按钮，校验格式、大小和数量。
- 同一文件移除后可以再次选择。
- 本轮图片仅在浏览器本地预览，不实际上传。
- “添加截图”表示提供待核查材料，不代表已实现图片鉴伪或文字识别。

### 示例

- 点击示例后填入输入框，并将焦点移至输入框。
- 用户可以继续编辑。
- 示例不会自动提交，也不展示预置真假结论。

### 辨真假按钮

- 允许“文字或链接”或“仅图片”作为输入。
- 完全空白且没有图片时，提示“请输入待核查内容，或添加截图”，并聚焦输入区。
- 有有效输入时，显示清楚的提示：

> 内容已准备好。核查服务尚未接通，目前无法生成真假判断。

- 提示可关闭，关闭后保留文字和图片。
- 不展示虚构的搜索进度、来源数量或核查结果。

## 七、实施约束

- 优先完成首页，保持后续接入真实核查接口的结构清晰。
- 可使用已有技术方案的 Next.js、TypeScript 和 Tailwind CSS；若仅交付独立静态原型，也可采用 HTML、CSS、JavaScript，并说明启动方式。
- 首页阶段不要求 Docker、数据库、Redis 或 API 密钥。
- 不在浏览器端放置服务密钥。
- 所有按钮、输入框、移除操作都支持键盘访问，图片按钮具有明确的可访问名称。
- 不创建登录、社区、热榜等本轮未要求的功能。
- 本轮以本地预览为交付目标。

## 八、验收与交付

交付完整页面源文件、启动说明和本地预览入口，并检查：

- PC 与手机宽度下布局完整，无横向溢出。
- 长文本可以换行、滚动和编辑。
- 示例可以填入，填入后可以修改。
- 图片可以选择、预览、移除；不合规图片有明确提示。
- 空输入提交和有效输入提交表现正确。
- 图片未被发送到外部服务。
- 页面明确标示核查能力尚未接通。
- 提供 PC 和移动端页面截图，说明实际完成的验证。

优先保证：**品牌醒目、输入顺手、手机好用、交互真实。**
